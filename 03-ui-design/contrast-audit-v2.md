# 对比度核算 v2

> 阶段 3 · 2026-11-21 · 基准：[design-v2-direction.md](design-v2-direction.md) 的 token 表
> 核算对象：`src/styles/global.css` 当前 token 的实际取值
> 取代：[contrast-audit.md](contrast-audit.md)（v1.1 调色板 + 朱红信号色，已不适用）

## 结论

- 逐对核算 67 项，**全部通过**。
- 本轮换用 Waystone AI 品牌铜色，同时把两个底色系的发丝线各加深一档，
  使装饰线在 `--bg-raised` 上也能维持 ≥1.3 的可见性。
- 最小余量出现在浅色「装饰发丝线（卡片底）」（1.31，+0.01）、深色「色带分隔线」（1.32，+0.02）、
  深色「装饰发丝线（卡片底）」（1.33，+0.03）。这三处都贴着门槛通过，改动任一相关色值都需要重跑本表。
- 与 v1 的数值**不可直接对比**：v1.1 的纸色（`#F6F2E9` / `#FBF8F1`）与朱红（`#B23A1B`）都已废弃。

## 1. 本轮变更的 token

| Token | 主题 | 旧值 | 新值 | 原因 | 最低实测 |
| --- | --- | --- | --- | --- | --- |
| `--accent` | 浅色 | `#B23A1B` | `#AC512D` | 对齐品牌铜色，同时保住正文链接 4.5:1 | 4.54（wash 底） |
| `--accent` | 深色 | `#F0805C` | `#E58A64` | 同上，色相回到铜 | 5.77（wash 底） |
| `--accent-wash` | 浅色 | `#F4E6DF` | `#F5ECE7` | 跟随新铜色重新调出的选中底色 | 4.54（accent 文字） |
| `--rule` | 浅色 | `#DDDAD1` | `#D9D5CB` | 原值在 `--bg-raised` 上仅 1.25，低于 1.3 可见线 | 1.31（raised） |
| `--rule` | 深色 | `#34312B` | `#37342E` | 原值在 `--bg-raised` 上仅 1.27 | 1.33（raised） |

`#C4633C`（标志里的铜）未直接用于文字：它在 `--bg` 上只有 3.87，正文链接不合格，
因此文字用深一档的 `#AC512D`，标志保持原铜色，两者是刻意的分工。

## 2. 判定口径

| 条款 | 目标 | 范围 |
| --- | --- | --- |
| 背景上的文字 | 4.5 | 正文、次要文字、元数据、按钮与胶囊文字、色带内文字、代码块 |
| `--ink-faint` 在 `bg` / `bg-raised` | 4.5 | 元数据与图注 |
| UI 边框 | 3 | 仅承担识别功能的控件边界与焦点指示，装饰线不在此列 |
| 装饰发丝线 | 1.3 | 低于此值在屏幕上会消失 |
| 不使用纯白文字 | — | 主按钮悬停文字用 `var(--bg)` |

半透明前景（`color-mix` 72% / 62% / 55% / 45%）按 sRGB 与 `--band-bg` 合成后再计算。

## 5. 未覆盖与限制

- **未重跑浏览器实测**。v1 曾用 Chrome DevTools Protocol 读取 4 个页面 × 2 主题的
  `getComputedStyle`；本轮只做 token 级核算。下次调整 token 时建议补跑，尤其是
  `color-mix` 合成值与 `:hover` 强制状态。
- **订阅输入框仍未渲染**（`newsletter.endpoint` 为空，页面回落到 mailto），
  边框、占位符、错误文本只能按 token 核算。
- **代码高亮未复核**：Shiki 使用 `github-dark-high-contrast`，其 token 色不来自本站变量。
- **页头半透明**按 92% 底色叠最暗内容的最坏情况估算，滚动时不会更低。
- **打印样式、OG 卡片、Pagefind 自带 UI** 不使用站内 token，不在本次范围。
