# 产品愿景 — Jin Lo

> Status: Approved for v1.0 · Owner: Founder / Editor · Last updated: 2026-11-13

## 1. 一句话定位

**Jin Lo 是一个英文个人博客，由一位在职软件工程师撰写长篇实战笔记，主题是构建能够经受现实考验的系统。**

不是教程农场，不是新闻聚合器，也不是个人日记。它是一份小而克制、声音有辨识度的出版物。

## 2. 为什么做这件事

三个问题驱动了这个项目：

1. **大多数工程内容优化的是点击量，而不是记忆点。** 清单体文章和“每周一个新框架”的帖子随处可见；而关于取舍、失效模式和长期维护成本的第一手记录却很少。
2. **海外读者很少听到来自 US/EU 圈层之外的工程师的声音。** 一种双语的、非硅谷视角的架构、流程与手艺观点，是真正的差异化。
3. **作者需要一个持久的公共资产。** 一个能产生复利的站点：写作练习、职业信誉，以及不依赖任何单一平台的入站机会（咨询、演讲、合作）。

## 3. 读者

| 分层 | 描述 | 他们想要什么 |
| --- | --- | --- |
| 主要 — 资深工程师 | 4–12 年经验，后端/平台/前端 | 有细节的取舍故事、可复用的检查清单 |
| 次要 — 技术负责人与创始人 | 负责架构与交付的人 | 决策框架、成本模型、沟通模式 |
| 第三 — 好奇的通才 | 有产品思维的读者 | 清晰的写作、没有术语墙 |

假设的阅读场景：英文环境，桌面或移动端，通常从 HN、Reddit、X 或转发的 newsletter 进入。他们只给一篇文章 **30 秒**，来决定是否再投入五分钟。

## 4. 价值主张

- **长篇、第一手、具体。** 每篇文章至少包含一个具体产物：一段 diff、一次基准测试、一张图、一张决策表或一份复盘。
- **安静的阅读体验。** 没有弹窗、没有自动播放、没有 Cookie 墙、没有布局抖动。阅读本身就是产品。
- **持久优先于时效。** 文章有发布日期，但不绑定新闻周期；三年后仍应有用。
- **对不确定性保持诚实。** 说“取决于”之后，要说明*取决于什么*。

## 5. 产品原则

1. **读者的时间就是指标。** 优化完成率和回访，而不是页面浏览量。
2. **交付最小而诚实的东西。** 没有伪造的“被收录于”标识，没有编造的订阅数。
3. **每个页面都必须在没有 JavaScript 的情况下可用。** JS 只做增强（主题、搜索、目录）。
4. **性能即编辑标准。** 一个缓慢的页面会与它要传达的信息自相矛盾。
5. **默认无障碍。** WCAG 2.2 AA 是底线，要经过测试，而不是假设。
6. **掌控平台。** 内容以 Markdown 形式存放在本仓库；托管服务可替换。

## 6. v1.0 的成功标准

| 目标 | 信号 | 指标（上线后 90 天） |
| --- | --- | --- |
| 可信的发布 | 站点可索引、快速、无错误 | Lighthouse 四大类别均 ≥ 95 |
| 内容基础 | 已发布的实质性长文 | 10 篇，每篇 ≥ 900 词 |
| 分发 | RSS + newsletter + 社交闭环 | 100 位 RSS 订阅者，50 个 newsletter 注册 |
| 被发现 | 搜索展示次数 | 每月 2,000 次展示，5+ 关键词进入前 50 |
| 手艺 | 回访读者 | 回访访客 ≥ 25% |

目标是刻意保守的：个人博客靠质量的复利增长，而不是靠上线时的流量峰值。

## 7. 非目标（v1.0）

- 评论、用户账号或任何服务端数据库。
- CMS 界面。在 git 中编辑 Markdown 就是工作流。
- 在证明有受众之前做变现（广告、付费墙、赞助）。
- 多语言发布。仅英文；双语视角体现在写作本身。
- 播客/视频。以后可能做，不属于本次构建。

## 9. 风险与缓解

| 风险 | 影响 | 缓解措施 |
| --- | --- | --- |
| 写作节奏中断 | 站点看起来像被废弃 | 预先写好 10 篇文章的储备；每两周发布一次；每月更新“Now”页面 |
| 内容读起来很泛 | 缺乏差异化 | 编辑规则：每篇文章都需要第一手产物或故事 |
| 技术栈过度设计 | 无法上线 | 静态站点、零运行时服务、一周构建范围 |
| SEO 不可见 | 无人发现 | 内置技术 SEO：sitemap、RSS、JSON-LD、canonical、OG 图片、快速 LCP |
| 平台依赖 | 流量脆弱 | 邮件列表 + RSS 是一等渠道；社交仅用于分发 |

## 10. 整个交付的完成定义

一个公共读者可以访问站点，理解作者是谁以及为什么写，浏览并搜索文章，在移动端舒适地读完一篇长文，通过 RSS 或邮件订阅，并分享带正确预览卡片的文章。作者可以添加一个 Markdown 文件、推送，并在几分钟内上线，无需任何手动步骤。
