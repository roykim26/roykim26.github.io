# 用户故事

> Stage 2 · v1.0 · Format: As a … I want … so that …
> Every story maps to requirements in `prd.md`; test coverage is tracked in
> `05-qa-testing/test-cases.md`.

## A. 读者 — 发现

### US-01 通过搜索或社交找到站点
作为一名正在搜索某个系统主题的工程师，
我希望在搜索结果中看到标题和描述清晰的相关文章，
以便我能快速判断它是否值得我花时间。

**验收**
- 给定一个文章页，被爬取时，`<title>`、meta description、canonical、OG 图片和 `BlogPosting` JSON-LD 均存在且有效。
- 给定一个已分享的文章 URL，在 X/LinkedIn/Slack 中展开时，渲染出带文章标题的品牌化 1200×630 卡片。
- 给定 sitemap，抓取时，它列出每篇已发布文章且不含草稿。

**关联需求：** FR-3.7、FR-7.1–7.5 · **优先级：** 必须

### US-02 理解写作背后的人
作为第一次访问的读者，
我希望知道是谁在写、为什么写，
以便我能信任内容并愿意订阅。

**验收**
- 首页首屏展示作者姓名、角色和定位。
- 关于页面用平实易懂的语言说明背景、主题和联系方式。
- 每篇文章末尾显示作者卡片，并链接到关于页面。

**关联需求：** FR-1.1、FR-5.1、FR-3.6 · **优先级：** 必须

### US-03 浏览所有文章
作为回访读者，
我希望有一个按时间排序的文章索引，
以便我不依赖 feed 阅读器也能补读。

**验收**
- `/blog` 按最新优先列出所有已发布文章，按年分组，并显示数量。
- 每行显示日期、标题、描述、阅读时长和标签。
- 草稿永不出现。

**关联需求：** FR-2.1、FR-2.6 · **优先级：** 必须

### US-04 搜索某个主题
作为记得关键词但记不住标题的读者，
我希望搜索归档内容，
以便不用一直滚动就能找到那篇文章。

**验收**
- 在 `/blog` 上聚焦/打开搜索时加载搜索 UI，并返回标题、描述、标签和正文的匹配结果。
- 初始页面加载时不下载任何搜索 JS。
- 禁用 JS 时，完整列表仍可阅读，并显示一条提示使用浏览器查找的说明。

**关联需求：** FR-2.2–2.5 · **优先级：** 应该

### US-05 按主题筛选
作为只对某个主题感兴趣的读者，
我希望按标签筛选或浏览，
以便阅读一个连贯的系列。

**验收**
- `/blog` 上的标签胶囊就地筛选列表，并更新结果数量。
- `/tags` 显示所有已使用标签及数量；`/tags/<tag>` 仅列出该标签。
- 未使用标签的 URL 返回 404。

**关联需求：** FR-2.4、FR-4.1–4.3 · **优先级：** 必须

## B. 读者 — 阅读

### US-06 在任何设备上舒适阅读
作为通勤时用手机阅读的读者，
我希望字体清晰、行宽合理、没有干扰，
以便我能毫无阻碍地读完一篇长文。

**验收**
- 桌面端正文每行 60–72 字符；移动端基础字号 16–18px。
- 没有弹窗、插页、自动播放或覆盖文字的吸底分享栏。
- 滚动时页头占用不超过 64px；阅读进度可见。
- 200% 缩放时文字仍可阅读，且不出现横向滚动。

**关联需求：** FR-3.1–3.2、NFR 性能/无障碍 · **优先级：** 必须

### US-07 在长文中导航
作为正在阅读一篇 2,000 词文章的读者，
我希望有目录和章节感知，
以便跳到需要的部分并知道自己在哪里。

**验收**
- 目录列出所有 h2/h3 标题，锚点链接可用。
- 目录在 ≥1200px 时吸顶，在移动端可折叠。
- 滚动时高亮当前章节。
- 标题锚点可通过键盘聚焦，并具有无障碍名称。

**关联需求：** FR-3.3–3.4 · **优先级：** 应该

### US-08 与同事分享文章
作为发现了有用内容的读者，
我希望一键分享和复制链接，
以便不离开页面就能发送出去。

**验收**
- 分享行提供 X、LinkedIn 和复制链接。
- 复制链接会给出可见的成功反馈，并在 Clipboard API 不可用时回退到选中 URL。
- 分享 URL 正确编码，并在新标签页中打开，带有 `rel="noopener"`。

**关联需求：** FR-3.5 · **优先级：** 应该

### US-09 继续阅读相关作品
作为投入的读者，
我希望看到相关和相邻的文章，
以便继续阅读，而不是走进死胡同。

**验收**
- 文章页显示最多三篇相关文章，先按共享标签、再按时间排序。
- 上一篇/下一篇链接存在且正确，包括时间边界情况（第一篇文章只显示“下一篇”）。
- 所有相关链接都可解析（无 404），并保持站点样式。

**关联需求：** FR-3.6 · **优先级：** 应该

## C. 读者 — 订阅

### US-10 不依赖算法地关注
作为偏好自主掌控的读者，
我希望有 RSS 和邮件两种选择，
以便不使用社交媒体也能关注。

**验收**
- `/rss.xml` 通过验证并包含完整文章内容。
- 首页和页脚提供 RSS 链接；文章页在分享行中提供。
- `/newsletter` 说明价值、频率和隐私，并提供可用的表单；未配置端点时提供 mailto 回退。

**关联需求：** FR-1.5、FR-6.1–6.3、FR-7.1 · **优先级：** 必须

## D. 运营者 — 发布

### US-11 几分钟内发布一篇文章
作为作者，
我希望添加一个 Markdown 文件并推送，
以便发布不会变成另一个独立项目。

**验收**
- 一个带有有效 frontmatter 的新文件会出现在首页、`/blog`、标签页、RSS、sitemap 中，并自动获得 OG 图片，无需任何其他改动。
- 非法的 frontmatter 会导致构建失败，并给出指明文件和字段的错误信息。
- 设置 `draft: true` 会将其从所有公开面移除。

**关联需求：** FR-10.1–10.3 · **优先级：** 必须

### US-12 安全地部署与回滚
作为运营者，
我希望部署可重复，并带有验证和回滚，
以便糟糕的改动不会长时间留在线上。

**验收**
- CI 在每次 push 和 PR 时运行构建、类型检查、链接检查和 SEO 检查。
- 部署是不可变的；回滚可在五分钟内恢复上一个构建。
- 部署后冒烟测试覆盖首页、索引、一篇文章、feed、sitemap 和 404。

**关联需求：** FR-11 · **优先级：** 必须

## E. 读者 — 边界情况

### US-13 落到失效链接
作为跟随过时链接的读者，
我希望看到一个有帮助的错误页面，
以便我仍能找到内容。

**验收**
- 404 页面使用站点框架，说明情况，并链接到 Writing、Tags、Home。
- 404 从 sitemap 中排除，并在托管平台上返回 HTTP 404。
- 在 JS 可用时，可从 404 页面进入搜索。

**关联需求：** FR-9.1 · **优先级：** 必须

### US-14 在禁用 JavaScript 时阅读
作为注重隐私的读者，
我希望内容与导航在无 JS 时仍可用，
以便我不会被脚本挡住。

**验收**
- 所有路由在服务端渲染内容和导航。
- 主题回退到 `prefers-color-scheme`。
- 搜索显示优雅的解释性回退；没有布局破坏或内容隐藏。

**关联需求：** NFR 兼容性 · **优先级：** 必须

### US-15 使用键盘或屏幕阅读器
作为使用辅助技术的读者，
我希望导航和播报可预测，
以便我能独立阅读和操作站点。

**验收**
- 跳过链接位于 tab 顺序首位，并将焦点移到 `<main>`。
- 每页一个 `<h1>`；标题层级不跳级。
- 所有控件都有无障碍名称；焦点始终可见；没有键盘陷阱。
- 移动端菜单和搜索对话框关闭时恢复焦点，并支持 `Escape`。
- 动效遵循 `prefers-reduced-motion`。

**关联需求：** FR-8.4、NFR 无障碍 · **优先级：** 必须
